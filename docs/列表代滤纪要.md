## 一、缺陷

血缘列表查询未钉封批代：批次封批升代后，上一代登记的有向边（邻代边）仍混入
当前代浏览结果，审计按错代追血统。根因在 `GET /api/lineage` 无代次过滤，
且 `lineage_edges` 行未钉登记时代次。

## 二、口径定义

- **正式边**：登记时钉死两端批次代次（`from_gen` / `to_gen`），且展示时钉代
  与批次当前代一致的血缘边。
- **邻代边**：钉代落后于批次当前代的边（封批升代所致）。属其它封批代的边，
  不得混入当前代列表。
- **跨代边**：登记时两端批次代次不一致的边。

## 三、封死口径：甲路径（唯一，折中禁用）

1. **列表只许当前代正式边**：`GET /api/lineage` 与
   `GET /api/lineage/batch/{id}` 只返回钉代 == 批次当前代的正式边，
   邻代边读时滤除，零增展示。
2. **跨代边拒收**：`POST /api/lineage` 登记时两端代次不一致 → 409 拒收，
   不落库（零增）。
3. **不设影子浏览草案**：乙路径（影子草案 + 代对齐晋升 + 回滚）弃用。
   双写会出邻代边串屏，禁止任何形式的双写/影子层/折中混合。
4. **手改代滤须抢血缘锁**：`POST /api/lineage/filter` 钉代滤前须抢
   `lineage:{batch_id}` 锁；同时争用仅存痕（`contention_log`），后到者
   不写业务；代滤只能钉当前代，跨代钉滤 409 拒收。
5. **禁止只改血缘页排版**：本修复以服务端钉代过滤为准，页面仅如实展示
   钉代列；导航分区不动。
